MAPG / 丸編設計 — Access VBA

ツールリファレンス

.accdb と src/ を行き来する4つのスクリプトの機能と概要。手順書（ワークフロー編）の対。スクリプト更新版（export v2 / import v3 / state v2 / deadcode v2）対応。

4つの早見表

ツール方向.accdbを変更中核の仕組み終了コード
accdb_export.py.accdb → srcしない（読取）SaveAsText＋正規化0=成功 / 1=失敗あり
accdb_import.pysrc → .accdbするLoadFromText（文字コード自動追従）0=成功 / 1=失敗あり
accdb_state.py.accdb 読取しない（読取）VBComponents 列挙0=OK / 1=NG・未検証 / 2=エラー
vba_deadcode_remove.py.accdb 手術するCodeModule.DeleteLines0=成功 / 1=失敗あり

役割の流れ：export で抽出 → AIや差分で確認 → import（モジュールのみ）で反映。 state はいつでも現状点検、deadcode_remove は不要プロシージャの外科的削除。

共通の更新：書き込み系（import / deadcode_remove）は .laccdb 検出で自動中止（export は警告のみ）・ 全スクリプトが終了コードを返却（バッチ組み込み可）・出力を UTF-8 化（リダイレクト時の ✓/⚠ による UnicodeEncodeError を解消）。

accdb_export.py .accdb の全コードオブジェクトを、Git向けに正規化したテキストとして src/ へ抽出する。
.accdb → src .accdbは読取のみ

何をするか

  • フォーム／レポート／モジュール／マクロ／クエリを SaveAsText で書き出し、テーブルスキーマは DAO で取得（データは含めない）。
  • 全ファイルを UTF-8／LF に正規化し、行末空白を除去して差分を安定化。
  • Gitを汚すノイズを自動除去：Checksum・PrtDevMode/Names・NameMap・GUID は常に除去、埋め込み画像/OLEは既定で除去（--keep-media で保持）。ページ幾何 PrtMip は保持。
  • 実行ごとに src/ を作り直す（.accdbで削除済みのオブジェクトを差分に反映するため）。
  • _manifest.tsv（安全名↔実名の索引）と .gitattributes を生成。
  • v2：--commit と .gitattributes のパスが --out に追従。抽出失敗があると自動コミットを中止（src/ は毎回作り直すため、失敗分が git 上「削除」に見える＝壊れたミラーの誤コミットを防ぐ）。.laccdb 検出時は警告（保存前の編集は抽出に反映されない）。

主なオプション

（位置引数）対象 .accdb のパス
--out DIR出力先（既定 src）
--no-tablesテーブルスキーマを抽出しない
--keep-media埋め込み画像/OLEも残す（既定は除去）
--commit "MSG"抽出後に add＋commit（push はしない。抽出失敗があれば自動中止）

入力 / 出力

入力：.accdb　／　出力：src/（forms・reports・modules・macros・queries・tables）＋ _manifest.tsv＋.gitattributes

使用例

py accdb_export.py MAPG.accdb
py accdb_export.py MAPG.accdb --commit "VBA抽出: 初回"
py accdb_export.py MAPG.accdb --keep-media
位置づけ

出力は「完全再構築用」ではなく レビュー/差分/最適化のためのミラー。画像・プリンタ設定などは .accdb が正本。

accdb_import.py src/ のテキストを LoadFromText で .accdb に書き戻す（export の対）。
src → .accdb .accdbを変更 フォーム/レポート既定ブロック

何をするか

  • 指定したオブジェクトを LoadFromText で反映。
  • 文字コード自動追従（v2の肝）：対象を一旦 SaveAsText して現行のBOMを判定し、同じ文字コード（CP932/UTF-16/UTF-8）＋CRLF で書き戻す。日本語Accessで UTF-16 を書いて文字化け・破損するのを防ぐ。
  • 反映前に .accdb を必ずバックアップ。テーブルは LoadFromText 非対応のため自動スキップ。
  • 安全な型は modules / queries。フォーム/レポートは既定でブロック（v3。解除は --force-risky のみ・非推奨）。マクロは △ 表示で反映可（バイナリ間引きの影響がないため）。
  • v3：.laccdb 検出時は反映前に自動中止（「Accessを閉じてから」を機械的に担保）。

主なオプション

accdb files...反映先 .accdb と、反映する src ファイル（複数可）
--allmanifest 全件を反映（テーブル除く）。v3：既定でフォーム/レポートを含まない＝実質モジュール/クエリ/マクロの一括反映
--force-riskyフォーム/レポートのブロックを解除（画像・ActiveX喪失の恐れ。通常は使わない）
--yes確認プロンプトをスキップ
--encodingauto（既定・自動追従）/ cp932 / utf-16

入力 / 出力

入力：src ファイル　／　出力：更新された .accdb＋バックアップ。反映後は VBE で コンパイル確認。

使用例

py accdb_import.py MAPG.accdb src\modules\共通モジュール.txt
py accdb_import.py MAPG.accdb src\modules\フォーマット.txt src\queries\設計原糸一覧マスタ.txt
注意

フォーム/レポートを書き戻すと、抽出時に間引いた画像・プリンタ設定・ActiveX（ListView等）が失われる。v3 からスクリプト側でも既定ブロックされるが、解除フラグの --force-risky は通常運用では使わないこと。フォームのコードは VBE に手貼り、デザインはデザインビューで直接編集する。

accdb_state.py .accdb の現在のVBA状態を 読み取り専用で点検する。
.accdb 読取 変更しない VBA信頼設定 要ON

何をするか

  • .accdb を開き、VBAコンポーネントとプロシージャを列挙（SaveAsText/LoadFromText/DeleteLines は一切呼ばない純粋な読取）。
  • deadcode_delete_list.tsv の削除対象が「消えているか」を検証。v2：accdbと同フォルダ→カレントの順で自動探索し、未検出/空なら検証をスキップして ⚠ を明示（従来の「0件で ✓」という偽の緑を解消）。
  • 復元されているべき束縛ハンドラ（代表サンプル）が「存在するか」を検証。
  • コンポーネント別プロシージャ数と総数を表示。
  • v2：終了コードを返す（0=OK / 1=NG・未検証 / 2=実行エラー）。バッチや pre-commit フックに組み込める。

主なオプション

（位置引数）対象 .accdb（省略時 MAPG.accdb）
--list FILE削除リストTSVを明示指定（既定は自動探索）

入力 / 出力

入力：.accdb（＋deadcode_delete_list.tsv：accdbフォルダ→カレントの順に探索）　／　出力：コンソールへの点検レポート＋終了コード（変更なし・バックアップ不要）。

使用例

py accdb_state.py MAPG.accdb
py accdb_state.py MAPG.accdb --list deadcode_delete_list.tsv
# 終了コード活用：点検OKの時だけ次の処理へ
py accdb_state.py MAPG.accdb && py accdb_import.py MAPG.accdb src\modules\共通モジュール.txt
メモ

「迷ったらまず実行」する安全な確認用。サンプル名は今回のデッドコード作業に合わせた値だが、コンポーネント数・プロシージャ総数の確認は汎用的に使える。

vba_deadcode_remove.py 未使用プロシージャを .accdb から 外科的に削除する。
.accdb 手術 .accdbを変更 VBA信頼設定 要ON

何をするか

  • CodeModule.DeleteLines で対象プロシージャの行範囲だけを削除。フォーム全体を作り直さないので画像・レイアウトは保持。
  • 行番号は保存値でなく削除直前に ProcStartLine/ProcCountLines で都度取得（コード変動に強い）。
  • deadcode_delete_list.tsv を読み込み（編集して取捨選択可）。
  • --sync-src で src のテキストからも同プロシージャを除去、--git で 1プロシージャ＝1コミット。
  • v2：.laccdb 検出時は中止。確認プロンプト→バックアップの順に変更（中止時にゴミを残さない）。ドライランでも --sync-src の src 側該当有無を表示。kind 列は表記ゆれ許容（Property Get 可）・不明値は黙殺せず理由付きスキップ。

主なオプション

accdb対象 .accdb
--list FILE削除リスト（既定 deadcode_delete_list.tsv）
--apply実削除（既定はドライラン＝無変更）
--sync-srcsrc/ テキストからも除去
--git1プロシージャ=1コミット（--sync-src 前提）
--yes確認をスキップ

入力 / 出力

入力：.accdb＋削除リストTSV　／　出力：更新された .accdb（＋バックアップ）、必要に応じて src 編集とコミット。

使用例

# まずドライランで対象を確認
py vba_deadcode_remove.py MAPG.accdb
# 実削除＋src同期＋1件1コミット
py vba_deadcode_remove.py MAPG.accdb --apply --sync-src --git
安全設計

既定ドライラン → --apply 時のみ自動バックアップ → 外科的削除でフォーム画像は無傷 → ドリフト耐性。集計は .accdb／src それぞれの実削除で計上（srcのみ削除は別掲）、失敗があれば終了コード 1。削除リストの正しさ（束縛ハンドラを含めない）が前提。

MAPG VBA ツールリファレンス ／ 共通の前提：Accessとbitを揃えたPython＋pywin32・リポジトリ直下で実行・.accdbは事前に閉じる（import / deadcode_remove は .laccdb 検出で自動中止）
