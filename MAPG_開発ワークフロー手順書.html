全体像：何が正本で、何がコピーか

  • 正本は MAPG.accdb。実際の修正はすべてここに反映される。
  • src/ は git 上のテキストミラー。差分の確認とAIへの受け渡しに使う。

01

エクスポート（.accdb → src → git）

いつ：Accessでフォームやコードを直した後／AIに依頼する前（最新を渡すため）

正本 .accdb からテキストを抽出し、git に記録する。Accessは閉じておく。開いたままだと保存前の編集は抽出に反映されない（export は .laccdb を検出すると警告して続行する）。

# リポジトリ直下で実行
cd C:\work\myapp
py accdb_export.py MAPG.accdb

# 何が変わったか確認してからコミット
git status
git diff --stat
git add -A
git commit -m "説明（例：設計Hメンテの計算ロジック修正）"
git push
確認： git diff --stat に、想定した変更だけが出ること。フォーム全体が大量に書き換わる等、身に覚えのない差分が出たらコミット前に止めて中身を見る。
02

AIへ修正を依頼する

いつ：コードの修正・分析・移行調査などを任せたいとき

渡すもの

該当する src/ のファイルをアップロードする。AIはそれを読んで修正する。

  • モジュールの修正 → src/modules/共通モジュール.txt など対象ファイル
  • フォームのコードの相談 → そのフォームの src/forms/〇〇.txt（コードを読ませる用）
  • DB全体の横断調査 → 上記に加え VBA相互リファレンス_*.xlsx

依頼の書き方（テンプレ）

対象：src/modules/共通モジュール.txt の 関数〇〇
やりたいこと：△△ になるよう直したい
制約：64bit維持・呼び出し側のインターフェースは変えない
出力：修正後のファイル全文（モジュール）／または変更箇所のプロシージャだけ

「何を・どう・触ってはいけない所」を具体的に書くほど安全で速い。

返ってくるもの（種類で扱いが変わる）

修正の種類AIの返し方反映方法
モジュール／クエリ修正後のファイル全文③ インポート（安全）
フォームのVBAコード変更するプロシージャだけVBEに手で貼る ／ 外科的スクリプト
フォームのデザイン（部品・配置）手順の案内Access デザインビューで操作
なぜ分ける？

フォームのコードを「フォーム.txt 丸ごと書き戻し」で反映すると、間引かれた画像・プリンタ設定・ActiveX（ListView等）まで再生成され、フォームが壊れる。だからフォームのコードは部品単位で VBE に貼るのが安全。

03

修正後のインポート（src → .accdb）

いつ：モジュール／クエリの修正を .accdb に反映するとき

モジュール／クエリ ＝ 安全（無損失）

Accessを閉じてから、対象ファイルだけを指定して書き戻す。開いたままなら .laccdb 検出で自動中止する（v3）。スクリプトが自動でバックアップを作る。

cd C:\work\myapp
py accdb_import.py MAPG.accdb src\modules\共通モジュール.txt

# 複数同時もOK
py accdb_import.py MAPG.accdb src\modules\共通モジュール.txt src\queries\設計原糸一覧マスタ.txt
反映後は必ず： Access → VBE（Alt+F11）→ [デバッグ] → [コンパイル] でエラーが無いか確認。

確認できたら git も合わせて更新する（②で受け取った修正を src に保存 → コミット）。

git add -A
git commit -m "共通モジュール：〇〇を修正"
git push

フォーム／レポート ＝ 書き戻し禁止

やってはいけない

--force-risky を使わない。フォーム.txt の書き戻しは v3 でスクリプト側でも既定ブロックされる（このフラグを付けない限り反映されない）。解除は画像・ActiveX 喪失を承知した緊急用。--all も v3 からフォーム/レポートを含まないが、意図しない一括反映を避けるためファイル指定を基本とする。

安全な方法

コードの修正：VBEで該当プロシージャを手で差し替える。
デザインの修正：Access のデザインビューで操作する（例：移行で消す ctlDlg もデザインビューで削除）。
反映後は ① エクスポート し直して git を最新化する。

安全ルール（毎回これだけ守る）

  • インポート前に Access を閉じる（ファイルロック回避。v3 は .laccdb 検出で自動中止＝機械的に担保）。
  • インポートはファイル指定を基本に。--all は v3 でフォーム/レポートを含まなくなったが、一括反映は避ける。--force-risky は禁止。
  • 反映後は必ず VBE でコンパイルしてエラーを確認。
  • 正常版のバックアップを1つ保管：MAPG_backup_20260629_165135.accdb（18件削除・131件健在のクリーンな復元点）。
  • 迷ったら現状確認：py accdb_state.py MAPG.accdb で .accdb が正しい状態か一目で分かる（終了コード 0=OK / 1=NG / 2=エラー。バッチに組める）。

困った時の戻し方

現状を点検する（読むだけ）

py accdb_state.py MAPG.accdb
# 終了コード: 0=OK / 1=NG・リスト未検証 / 2=実行エラー

.accdb をバックアップから復元する

# 先にAccessを閉じる
Move-Item MAPG.accdb MAPG_ng_$(Get-Date -Format yyyyMMdd_HHmmss).accdb
Copy-Item MAPG_backup_20260629_165135.accdb MAPG.accdb

git を前の版に戻す

git log --oneline -5
git reset --hard <戻したいコミット>
git push --force origin main
